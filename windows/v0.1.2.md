# Cronq for Windows v0.1.2 (beta)

Written for: you (the maintainer), as release notes and a test checklist.

## What's new

### 1. Lock (Alt+K)
- Press **Alt+K**: the overlay hides and **every other Cronq shortcut stops working** (Alt+X/G/A/S/F/D/P/M/W).
- No confirmation. It is instant and reversible.
- While locked, Alt+K and Alt+X are swallowed so the app you are using never receives them.
- Lock is **not saved**. Quitting and restarting Cronq (or signing in again) starts unlocked.

### 2. Unlock (Alt+K+X)
- Hold **Alt**, press **K** and **X** together (either order). Shortcuts work again and the overlay reappears with an "Unlocked" toast.
- This is the only chord that does anything while locked, apart from Alt+Shift+K.

### 3. Kill switch (Alt+Shift+K)
- Press **Alt+Shift+K**: a red box appears in the middle of the screen: *"Kill Cronq permanently?"*
- **Enter** = confirm. **Esc** = cancel. No answer for **15 seconds** = cancel.
- The box never takes focus, and Enter/Esc are only captured while it is on screen.
- Works while locked.
- On Enter, Cronq quits and a hidden cleanup script (`killswitch.ps1`, run from `%TEMP%`) removes it from the PC:
  - every Cronq process (overlay, supervisor, WebView2 helpers that hold its profile)
  - autostart: Run / RunOnce registry values, Startup-folder shortcuts, any scheduled task named *cronq*
  - Start Menu folder and shortcuts, Desktop shortcuts (`.lnk` only)
  - the `cronq` entry in your user PATH, and the Apps & features (uninstall) entry
  - the install folder (`%LOCALAPPDATA%\Programs\Cronq`)
  - `%LOCALAPPDATA%\cronq` (WebView2 profile, ChatGPT login, logs), `%APPDATA%\cronq` (config)
  - **`Pictures\cronq` (your screenshots)** and leftover `cronq*` files in `%TEMP%`
- It cannot be undone. To use Cronq again, download and install it again.
- Portable / developer builds (not in `%LOCALAPPDATA%\Programs\Cronq`): only Cronq's own files are deleted, never the whole folder.

### Other changes
- Installer, PowerShell dev installer and `make-dist.ps1` now ship `killswitch.ps1`.
- New tests: `lock_logic_test` (key logic) and `killswitch_script_test.ps1` (cleanup script; the real-deletion part only runs on CI).
- Spec (`shared/spec/behavior.md`) and `windows/README.md` document the new shortcuts. Linux is not changed yet.

## How to test it (on a real Windows PC)
1. Install v0.1.2 (or build and install from this branch). Confirm the overlay opens with Alt+X.
2. **Lock:** Alt+K. The overlay hides. Alt+X, Alt+G, Alt+P etc. do nothing. Notepad does not receive Alt+K or Alt+X.
3. **Unlock:** hold Alt+K+X. The overlay returns. Shortcuts work again. Repeat with X pressed before K.
4. **Restart:** lock, run `cronq kill` then start Cronq. It starts unlocked.
5. **Cancel the kill:** Alt+Shift+K, then Esc. Nothing is removed. Repeat and wait 15 s. The box closes by itself.
6. **Lock + kill:** Alt+K, then Alt+Shift+K shows the box. Esc cancels.
7. **Real kill (use a VM or a spare account first):** Alt+Shift+K, Enter. Within about 20 seconds check:
   - Task Manager: no `cronq`, `cronqw` or `msedgewebview2` using the Cronq profile
   - `%LOCALAPPDATA%\Programs\Cronq`, `%LOCALAPPDATA%\cronq`, `%APPDATA%\cronq` and `Pictures\cronq` are gone
   - Start Menu has no Cronq, Settings > Apps no longer lists it, Task Manager > Startup has no Cronq
   - `echo %PATH%` has no Cronq entry (new terminal)
   - Sign out and in: Cronq does not return

## Known limits (read before relying on it)
- **Not verified on real Windows yet.** Logic is unit-tested and the build passes under Wine; the PowerShell script has only been reviewed by hand plus a CI dry run.
- A single Enter confirms an irreversible wipe. The 15 s timeout and the red box are the only guards.
- Needs Windows PowerShell 5.1 (`powershell.exe`, built into Windows). If your company policy blocks PowerShell, Cronq will quit but the cleanup will not finish.
- Unsigned build: antivirus or SmartScreen may be suspicious of a program that runs a hidden PowerShell script that deletes files and startup entries.
- If `killswitch.ps1` is missing (an old v0.1.0/v0.1.1 install, or a build run outside an install), Alt+Shift+K shows "Kill failed" and Cronq keeps running.
- `cronq show` (command line) still shows the overlay while locked. The lock only blocks the keyboard shortcuts.
- Not available on Linux yet.

## Supported Windows versions
| | Supported |
| --- | --- |
| Windows 11 (21H2 and later), 64-bit | Yes, WebView2 is built in |
| Windows 10 version 2004 (build 19041) and later, 64-bit | Yes, the installer fetches the WebView2 runtime if missing |
| Windows 11 on ARM | Should work through x64 emulation, untested |
| Windows 10 before 2004, Windows 8.1, 8, 7 | No, the installer refuses (`MinVersion=10.0.19041`) |
| 32-bit Windows | No (x64 only) |
| Windows Server | Untested; needs Windows 10 2004 equivalent (Server 2022) plus WebView2 |

No Administrator rights are needed. Everything installs per-user.
